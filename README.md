# AdaPres

Content- and hardware-aware adaptive precision (INT8 / FP16 TensorRT engines) for real-time
video object detection. Research code for the IRIS 2027 submission; see `PLAN.md` for the
full protocol and `claude.md` for the execution rules.

**Execution split.** All dataset and GPU work runs in Kaggle notebooks (`notebooks/`). The local
machine only edits code, runs unit tests on synthetic fixtures, lints, validates configs, and
renders tables and figures from downloaded `results/`.

## Layout

```
configs/            default.yaml (all tunables), preregistration.yaml (frozen H1–H5),
                    kaggle.yaml (repo URL baked into notebooks), locked/ (later)
src/adapres/        package; notebooks only call into it
  config.py         YAML load + schema validation
  repro.py          seeds, git hash, environment capture
  results.py        results writer; refuses to write without meta (seed, git, env, config hash)
  envcheck.py       GPU / TensorRT / ONNX Runtime / NVML probes (Kaggle only)
  data/             bdd_mot.py (parse + layout discovery), classmap.py, subsets.py,
                    slices.py, splice.py
  eval/             coco_gt.py (GT → COCO JSON), coco_metrics.py (AP from COCOeval)
  pipeline/         build_bdd_subsets.py (notebook 01's workhorse)
scripts/            env_check.py, build_bdd_subsets.py, make_notebooks.py, make_repo_zip.py
notebooks/          GENERATED by scripts/make_notebooks.py; do not hand-edit
tests/              unit tests on synthetic fixtures (a few KB)
results/            committed small JSON/CSV only (downloaded from Kaggle)
logs/               local command logs
data/ cache/        gitignored, never committed
```

## Getting the repo into Kaggle

**Primary: private GitHub repo + Secret `GH_TOKEN`.**
1. Create a private GitHub repo and push this repo to it. Put its HTTPS URL in
   `configs/kaggle.yaml` (`repo_https`), run `scripts/make_notebooks.py`, then commit and push.
2. GitHub → Settings → Developer settings → Fine-grained tokens → *Generate*: repository access =
   only this repo; permissions: *Contents: Read-only*. Copy the token.
3. In each Kaggle notebook: *Add-ons → Secrets → Add a new secret*, label `GH_TOKEN`, paste the
   token, and tick the checkbox to attach it to the notebook.
4. Cell 1 clones `repo_ref` (default `main`) into `/tmp/adapres`. That location is outside
   `/kaggle/working`, so the clone is never saved into notebook output. The token is passed as a
   one-off HTTP header: it is never written to `.git/config` or printed.

**Fallback: repo zip as a Kaggle dataset** (when the Secret or GitHub isn't available).
1. Locally: `.venv\Scripts\python scripts\make_repo_zip.py` → `dist/adapres_repo.zip`. It contains
   committed files only, plus a `GIT_COMMIT` file. The script refuses to run if tracked files are
   modified.
2. Kaggle → *Datasets → New Dataset* → upload the zip (Kaggle extracts it) → private.
3. In the notebook: *Add Data* → your dataset. Cell 1 uses it automatically if the clone fails.

## Deviations from PLAN.md (report these in the paper)

- **D1 (PLAN §3.5, §4.1): calibration and test both come from BDD100K MOT *val*.** The Kaggle
  mirror (`tcjpaperdatasets`) provides MOT tracking images for val only. Calib (20 clips) and
  test (40 clips) are disjoint, seeded (`seed=2027`), time-of-day-stratified clip sets from
  official MOT val. All weights, thresholds, K, δ, INT8 calibration frames and slice thresholds
  are fit on calib only. Test is touched once per locked config. Consequence: calib and test share
  the official split's capture distribution, which is slightly less conservative than
  train→val. `selection.json` records the exact clip IDs and its SHA-256.
- **D2 (triggered, confirmed on Kaggle 2026-11-20): time-of-day fallback.** BDD MOT `box_track_20`
  labels carry no `timeofday` attribute, so strata come from Otsu on each sequence's median-frame
  luma (all 200 val clips; luma only, no labels or outcomes). Values are in
  `results/bdd100k_mot/bdd_subsets/report.json`. Luma cannot separate
  dawn/dusk, so that target is folded into daytime. `selection.json` and `report.json` record
  which method was used.
- **D3: ignore regions.** BDD `other person` / `other vehicle` / `trailer` boxes are written as
  `iscrowd=1` boxes for *every* evaluated class (`classmap.ignore_mode`). A detection of any class
  on those regions is therefore neither TP nor FP. Per-box `crowd=true` stays `iscrowd=1` within
  its own class.
- **D4: AP extraction.** pycocotools 2.0.11's `summarize()` hardcodes `maxDets=100` for
  `stats[0]`. Since PLAN uses `max_det=300`, AP is read from `COCOeval.eval['precision']`
  (`eval/coco_metrics.py`), not from `stats`.

- **D5: software stack.** The Kaggle image (2026-11-20) has Python 3.13 and torch 2.11 built for
  CUDA 13.0, so TensorRT uses the `tensorrt-cu13-*` wheels from `pypi.nvidia.com`. ONNX Runtime
  GPU (CUDA 12 build plus its own CUDA libraries) is only the INT8 fallback. If its CUDA probe
  fails, that is recorded and shown as a warning, not a stop (`env.require_ort_cuda`). Exact
  versions are locked in `requirements-kaggle.txt` after the first successful run.
